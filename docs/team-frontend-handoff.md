## 1. 项目是做什么的

Family Law Wise 服务美国家庭法律师及其客户，当前试点聚焦 **New Jersey 离婚案件的财务资料收集**。

律师建立事项、邀请客户；客户填写问卷，系统根据答案产生资料清单；客户交件或说明无法提供；律师接受材料或要求补交。双方需要围绕事项及文件沟通。产品希望通过 Wise AI 提示下一步，也提供一般信息问答及联系律师的入口。

长期方向包括经过律师确认的财务事实、NJ Case Information Statement（CIS）草稿及附件导出。跨州扩展需要各州自己的表格与规则，不能直接将 NJ 模板视为全美通用。

必须区分：

- **客户已提交**：材料交给律师审阅。
- **律师已接受**：材料满足相关清单要求。
- **收集完成**：事项满足团队确定的收尾条件。
- **文件数量与清单进度**：一份文件可以对应多个要求，进度按要求计算。

## 4. 本轮范围与完成含义

**第一轮只安排前端业务完成工作。** 页面、路由、表单校验、条件规则、业务状态、文件本地预览、消息及 AI 演示交互都在范围内。使用统一样例数据和前端共享状态验证。

本轮不承担数据库、真实认证、邮件发送、S3 上传、模型接入及服务器接口。演示邀请、文件提交和 AI 回复应明确标识其演示性质。跨浏览器同步、刷新后的持久保存，以及真实数据访问控制，不作为本轮通过条件。

现有阶段计划未把持久化真人消息或一般 AI 咨询纳入原始第一阶段。这里安排的是它们的前端交互，不修改服务端阶段计划或沿用原计划的工期承诺。

第一轮需要保证基本可用：手机关键按钮可见，内容可阅读，表单可以操作，错误能理解。全面配色、排版、卡片、动效与视觉统一提升，在第一轮通过后另行安排。

### 7.2 共用状态与验收环境

- 同一个事项、要求、文件、消息使用稳定且一致的 ID。
- 计数和进度来自共用状态，不在各页分别写死。
- 上传、退回、接受、补交、发送消息等操作，要更新同一份前端状态。
- 业务状态调整要同时检查列表、详情、客户视图及活动记录。
- 集成演示在同一个浏览器应用会话内切换律师和客户页面；刷新会重置当前原型。不同浏览器／独立标签页的实时同步不属于本轮要求。
- 每个负责人验证自己的流程，并请另一位成员检查交接点；成员 1组织三包联合验收。

## 8. 第一轮联合验收

以下全部通过后，才进入第二轮分工：

1. 从空白 NJ 样例事项开始，填写必要问卷；返回、继续、添加／修改／删除账户后数据和清单保持一致。
2. 客户选择本地文件，取消／换文件后明确提交；律师队列、客户端确认及清单都显示待审。
3. 律师退回并说明原因，客户看到后补交；新版本待审，旧文件和审阅决定可追溯。
4. 律师接受后，相关要求、进度、事项队列及活动按规则更新。
5. 客户提交、无法提供和律师完成符合已记录的业务条件。
6. 律师与客户交换样例消息；内部备注只在律师视图出现，文件关联及未读正确。
7. AI 显示与当前状态一致的下一步，进入正确任务；一般问题可演示，个案问题可转律师消息。
8. 主要操作有明确结果；空列表、找不到记录、必填错误等状态可理解；手机能完成核心操作。
9. 三位负责人合入后执行 `npm run lint` 和 `npm run build`，并实际走通上述流程；构建通过与业务验收分别记录。

每个任务交付时写明：完成的业务行为、改动位置、验证步骤、实际结果及尚未解决的问题。本文中的复选框初始均为未完成，不代表测试已经执行。

## 9. 第二轮如何开始

第一轮验收后，重新做一次桌面和手机 UI review，汇总信息层级、公共组件、导航、文字可读性、点击区域、间距、配色及视觉一致性问题。

根据这份实际问题清单和第一轮工作量，再分配三个人的第二轮任务。第二轮仍保留已验收的业务行为、现有骨架及架构基线。

财务事实确认、CIS 映射、CIS 导出及多州规则属于后续产品阶段，按 `nj-cis-plan.md` 单独安排。有财务画像画面不代表这些业务已经完成。

## 10. 本地开始工作

在仓库根目录执行：

```bash
npm ci
npm run dev
```

开发前阅读 `AGENTS.md`。按该文件要求，修改 Next.js 代码前先阅读 `node_modules/next/dist/docs/` 下与本次改动有关的指南；依赖或指南不可用时先解决环境问题，不凭旧版本经验改写路由约定。

每位成员先复现自己业务包的当前行为，确认缺口；再从最小可验收任务开始。开发过程中持续合入和检查交接点，不把所有集成问题留到最后。
